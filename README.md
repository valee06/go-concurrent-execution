# Go: Concurrent Execution

Проект о конкурентности в Go: горутины, каналы и примитивы пакета `sync` (`WaitGroup`, `Mutex`, `Once`, `RWMutex`). Нужно научиться синхронизировать горутины, обмениваться данными через каналы и избегать состояний гонки.

> **Статус: в работе.** Готово первое задание; остальные ещё впереди.

## Задания

| № | Каталог | Задание | Статус |
| - | ------- | ------- | ------ |
| 1 | `ex00` | Секундомер для асинхронных задач (`sync`, без каналов) | готово |
| 2 | `ex01` | Генератор и возведение в квадрат через каналы | заготовка |
| 3 | `ex02` | Тикер с остановкой по сигналу `SIGINT` / `SIGTERM` | запланировано |
| 4 | `ex03` | Бонус: потокобезопасный LRU-кэш на дженериках | запланировано |

## Реализовано

### `ex00` — секундомер для асинхронных задач

Программа принимает два аргумента: `-n` — количество горутин и `-m` — максимальное время сна в миллисекундах. Каждая из `n` горутин засыпает на случайное время до `m` мс; после того как все завершились, программа печатает пары «номер горутины — время сна», отсортированные по убыванию времени сна (при равенстве — по номеру).

```bash
cd src
go run ./ex00 -n 4 -m 300
```

```
Номер горутины: 3, время сна: 249
Номер горутины: 2, время сна: 67
Номер горутины: 1, время сна: 56
Номер горутины: 0, время сна: 17
```

Как устроено:

- горутины запускаются в цикле, ожидание их завершения — через `sync.WaitGroup`;
- общий срез результатов защищён `sync.Mutex`, поэтому записи из разных горутин не приводят к гонке;
- время сна выбирается через `math/rand/v2`;
- аргументы разбираются пакетом `flag`, некорректные значения (`n < 0` или `m <= 0`) завершают программу с ошибкой;
- по условию задания каналы здесь не используются.

## Что дальше

Задумка оставшихся заданий:

- **Генератор и квадраты (`ex01`).** Два конвейерных этапа на каналах: генератор отправляет числа от `K` до `N` в первый канал, функция возведения в квадрат читает его (канал только на чтение) и пишет результаты во второй, `main` печатает их. Каналы создаются внутри функций и закрываются по завершении работы.
- **Тикер (`ex02`).** Асинхронный счётчик «Tick `i` since `t`» с интервалом `K` секунд без `time.After` и `time.Ticker`, который завершается сообщением `Termination` по `SIGINT` / `SIGTERM`.
- **LRU-кэш (`ex03`).** Пакет с типом `Cache` на дженериках: операции `Set`, `Get`, `Clear` за O(1), потокобезопасность и тесты на вытеснение редко используемых элементов.
